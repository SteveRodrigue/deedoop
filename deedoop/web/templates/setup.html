Schedule

Unticked, deedoop never scans on its own: it scans only when you press Start scan. Ticked, it starts one scan a day when the window opens and stops it at the end time; the next night's scan skips files already read, so it carries on where it stopped. If the scan finishes early, nothing more runs until the next day. The same start and end time means no end time. Scans you start yourself are never stopped.

Changes to your files

deedoop only reads your disks until you turn this on. Even then, nothing happens until you confirm a list of changes on the Changes screen, and every file is checked again just before it is touched.

Container access to /mnt: {% if gate.writable %}read-write{% else %}read-only To allow changes, edit the container and set the /mnt path's access mode to read/write.{% endif %}

Benchmark

Reads a sample of large files from each selected disk alone, then from 2, 3, … disks at once, and measures hashing speed. It only helps tune Disk mode: it proposes one disk at a time or parallel, how many disks to read together and hash threads per file. Nothing changes until you apply it. Optional: one disk at a time is a safe default. Takes about {{ 10 }} seconds per disk and combination, and cannot run during a scan.
